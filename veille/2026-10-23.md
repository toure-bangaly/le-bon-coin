# Veille du 2026-10-23

## Ce que j'ai regardé aujourd'hui
Relecture complète des 31 veilles précédentes (09-09 au 10-22) pour ne rien répéter, puis recherches sur le blocage des liens WhatsApp dans les navigateurs intégrés de Facebook et Instagram, sur l'amélioration progressive des formulaires sans JavaScript, et sur les motos électriques en Afrique de l'Ouest (écarté, hors périmètre). Le terrain déjà couvert par les veilles précédentes est très large ; deux pistes concrètes et neuves en sont sorties aujourd'hui.

## Idées retenues

**1. Avertir l'acheteur coincé dans le navigateur intégré de Facebook ou Instagram**
Plusieurs guides 2026 documentent un problème connu : un lien ouvert depuis l'app Facebook, Instagram ou Messenger passe par leur navigateur intégré (webview), qui refuse souvent de transmettre un lien `wa.me` à l'application WhatsApp installée. L'utilisateur tombe alors sur une page de connexion WhatsApp Web inutile sur mobile, juste au moment de cliquer.
C'est pertinent ici parce que le site est justement pensé pour être partagé sur WhatsApp, Facebook et Instagram (la section « Notre histoire » dit déjà que les clients envoient le contact à leurs cousins et voisins) : un acheteur de Korhogo qui ouvre le lien reçu dans Messenger ou Instagram, puis tape sur « Réserver un essai » ou « WhatsApp », peut échouer sans comprendre pourquoi, exactement au moment de la conversion.
Concrètement : dans `assets/js/app.js`, détecter `FBAN`/`FBAV` ou `Instagram` dans `navigator.userAgent` et, si trouvé, afficher une petite bannière discrète (réutilisant le style déjà existant de `.tag-neutral` / `.delivery-soon`) du type « Vous êtes dans le navigateur de Facebook/Instagram. Touchez ⋮ puis « Ouvrir dans le navigateur » pour que WhatsApp s'ouvre normalement. » Aucune dépendance ajoutée. Effort : 1h30 à 2h (détection, bannière, test réel en partageant le lien depuis Instagram et Messenger). Coût : 0.

**2. Donner au formulaire newsletter le même filet de secours sans JavaScript que le questionnaire**
Le site applique déjà ce principe pour le questionnaire : un `<p class="no-js-only text-muted">` renvoie vers WhatsApp quand JavaScript est absent (`index.html`, ligne 351). Le formulaire newsletter, lui, n'a ni attribut `action` ni équivalent.
Sans JavaScript, cliquer sur « Je découvre mes motos » ne fait rien d'utile : rechargement silencieux, sans message d'erreur ni confirmation. L'acheteur croit avoir laissé son email pour le code `BIENVENUE10`, alors que rien n'est arrivé nulle part. C'est un trou de cohérence avec un principe déjà appliqué ailleurs sur ce même site, pas une nouvelle fonctionnalité.
Concrètement : dans `index.html`, section `#newsletter`, ajouter un `<p class="no-js-only text-muted">` sur le modèle de celui du questionnaire, invitant à demander le code promo directement sur WhatsApp si JavaScript est désactivé, et marquer le formulaire `js-only` pour qu'il ne s'affiche que si le script peut le traiter. Classes CSS déjà existantes, aucune nouvelle règle. Effort : 45 minutes. Coût : 0.

## Écarté et pourquoi
- **Montée des motos électriques en Afrique de l'Ouest (Spiro, Ampersand)** : marché réel, mais c'est une question de quelles motos Bangaly achète pour les revendre, pas une modification du site statique. Hors périmètre de cette veille technique.
- **Compteur « X personnes regardent cette moto » ou « vendue aujourd'hui »** : même écueil que le compteur de ventes déjà écarté le 12 octobre, aucune donnée réelle pour l'alimenter honnêtement, risque de pratique commerciale trompeuse contraire à la promesse d'honnêteté du site.
- **Correction via lien `intent:` Android ou bibliothèque de détection de webview plus complète** : plus robuste en théorie, mais spécifique à Android, fragile sur iOS, plus lourd à maintenir seul à temps partiel qu'une simple bannière d'avertissement. La bannière retenue couvre l'essentiel du besoin plus simplement.
- **Fiches produit d'Expat-Dakar, Afribaba, Avito Côte d'Ivoire** : recherche infructueuse, rien de fiable trouvé sur leurs champs réels en 2026 ; à retenter une autre fois avec un accès différent.
